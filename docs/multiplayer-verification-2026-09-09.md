# 多人联机验收记录 · 2026-09-09

## 交付范围

完成面向跨网络好友联机的版本：2–8 人免费房、邀请链接/房间码加入、准备与倒计时、权威驾驶/道具同步、10 秒断线恢复、独立编号的共同下一场房间，以及同域部署和 Netlify 分离部署配置。现已上线：网页 <https://kartclub.xyz>，Render 赛事服务 <https://kart-club.onrender.com>。

## 公网部署验收（当日补充）

- Render 新加坡 Docker 服务、一个 0.5 CPU / 512 MB 实例及 1 GB 持久化盘已创建，基础费用 $7.25/月；Docker 构建和生产启动成功。
- GitHub 和 Netlify 的构建变量均为 `VITE_GAME_SERVER_URL=https://kart-club.onrender.com`；实际发布脚本已包含该地址，正式网页显示 `Race service connected`。
- 正式网页实际创建免费房间成功，弹出 8 个席位、准备按钮和 `https://kartclub.xyz/?room=…` 邀请链接；核对后已退出测试房间。
- 远端 HTTPS 健康检查、协议版本、来自 `https://kartclub.xyz` 的 API 和匹配跨域预检通过。
- 9 个独立模拟账户：8 个真实公网 WebSocket 客户端进入同一房间，第 9 个收到满员提示。
- 倒计时离开导致取消，剩余 7 人共同进入一个新的下一场房间；全部准备后进入比赛，服务器确认驾驶输入和车辆位移。
- 主动中断其中一个连接后，恢复到原会话，其他玩家同步看到恢复状态；完成后测试客户端均已离房。
- 公网测试发现 Colyseus 将应用错误码 520–526 用作 HTTP 状态，导致 Cloudflare 替换错误内容。修复提交 `74b5a3e` 将此范围映射为 HTTP 400 并保留 JSON 错误码和具体提示；不存在/已满房间回归测试修复前失败、修复后通过。实际公网已返回 HTTP 400 JSON。
- 修复后完整测试 **833 项通过，0 项失败**，TypeScript/Vite 生产构建通过。

这轮公网验证从当前电脑发起多个独立客户端，尚未使用手机移动网络与另一台设备完成实际对局；不同运营商的延迟和跨设备体验仍应按部署说明实测。

## 实测

- 最终全量 `npm test`：**711 项通过，0 项失败**。运行日志：`output/multiplayer-tests-20260909.log`。
- `tests/multiplayer-*.test.ts`：服务地址与安全协议校验、邀请链接解析、身份按服务隔离、初始化去重、静态站点 HTML 回退提示、取消加入、取消再来一局、免费 10 分钟等待、门票 30 秒等待、版本拒绝、掉线撤销准备。
- 真实生产服务集成：9 个独立身份，8 人进入同一房间，第 9 人被拒绝；倒计时中离开导致取消，7 名玩家同时选择下一场仍只得到一个共同房间；驾驶输入得到服务端位移与序号确认；掉线后恢复同一身份；免费余额保持不变。
- 过期下一场：真实等待门票房超过 30 秒，晚到好友收到房间结束提示，同时保留原房间。此回归测试修复前失败、修复后通过。
- `npm run smoke`：两名车手合法完赛，模拟奖金结算、领取与奖池余额通过。
- `npm run validate:network`：4 人分别在 0 / 80 / 150ms 模拟 RTT 下完成比赛；150ms 场景加入 2% 应用消息丢失；8 人场在 150ms / 2% 下执行 5 秒断线恢复，所有车手合法完赛、结果及最终驾驶资源一致。另通过 10 次房间循环和免费余额不变检查。详细结构化记录位于 `artifacts/network-validation.json`。
- 真实 Vite 验证：账户 API、匹配和 `/socket` WebSocket 均通过同一个临时网页端口，成功收到玩家快照。脚本位于 `output/multiplayer-20260909/verify-dev.ts`，需要先启动独立测试服务 2599。
- 浏览器检查：生产入口可载入游戏；邀请链接直接进入多人页并预填房间码；实际创建房间、另一个独立标签页通过邀请加入、双人名单及准备状态更新、关闭房间返回大厅。界面截图检查后调整了浅色背景下状态和计时文字的对比度。
- `npm run build`：TypeScript 和 Vite 构建通过。保留现有的大资源包提示，未在本次联机工作中重构美术资源。

## 审查

独立只读审查发现两个问题，均已添加回归验证并修复：异步离房期间的显式退出会取消下一场连接；返回下一场地址前检查其权威比赛阶段，避免向晚到好友提供已取消的房间。

## 验证边界

上面的早期延迟/丢包测试由应用消息层模拟，公网部署补充测试连接的是真实 Render 服务。Docker 镜像现已在 Render 构建并运行成功。两类测试均不能代替不同网络、不同设备的实测，仍需完成 [部署说明](multiplayer-deployment.md) 中的手机移动网络验收。
