## 可行动发现

### IR01｜P2｜道具带账本只记最后圈号，回退旧圈可重复领取

- 位置：`shared/items.ts:163`、`:168`（初始化 `:51`）。
- 原因：`pickedLaps[band]` 只保存最近一次领取的圈号，且圈号取 `Math.floor(c.progress)`；赛车合法进度允许逆行减小。领取新圈会抹掉该带旧圈的领取历史。
- 复现：同一车在进度 `0.06` 领取带0，正常完成下一圈后在 `1.06` 再领；用掉库存，逆行回旧圈带0，再正向经过。使用同样 `stepItems` 状态边界的针对性脚本得到三次资源 `missile / missile / boost`，账本 `0 → 1 → 0`。这不是只切换同圈车道，现有测试未覆盖跨圈回退。
- 影响：不满足 AC34 的“单车、单圈、带ID一次”，存在重复刷资源路径。
- 建议：保存已领取元组或使用能拒绝历史圈号的单调账本；保持满库存不覆盖、复位不发放的规则。增加先领圈0、再领圈1、退回圈0的回归。

### IR02｜P2｜组合命中逐次乘速，没有减速下限或恢复保护

- 位置：`shared/items.ts:87`–`:99`，投射物逐个调用 `hit` 的 `:180` 起。
- 复现：速度40的同一受害车附近放三枚未过期、指向它的飞弹，单次 `stepItems(..., 1/60, ...)` 后速度为 `3.645`（`40×0.45³`），命中计数3、slow=1.5。当前护盾只阻挡其中一次，剩余攻击仍逐次乘速。
- 影响：已有道具组合不遵循规格11.1的减速下限/总效果优先级；AC35未完整验证。当前不是新增P2模式的要求，是已有攻击逻辑的组合正确性。
- 建议：明确有限的受击恢复/免疫语义，统一一次性护盾消耗和减速合并，避免同tick叠乘；覆盖护盾、复位/幽灵资格、连续飞弹和陷阱的组合。不要把仅存在1.5秒计时器等同于已实现效果下限。

### IR03｜P2｜DNF同进度排序没有使用到达该进度的时间

- 位置：`shared/rules.ts:44`；`server/room.ts:231`。
- 原因：房间维护 `Seat.progressAt`，但 `classify` 只接收 `Car`，同进度比较 `car.time`，无法知道谁先到达该进度。正常同刻截止的两车 `car.time` 相同，最终退化为ID排序；中途退出者则按退出时总用时比较。
- 复现：A、Z合法进度相同，Z更早到达后停车，A稍后到达；两者在300秒截止时time相同，结果会按ID把A排前，而不是Z。该顺序仅影响DNF展示，不会增加完赛资格/奖金。
- 建议：让排序使用权威到达时刻；同时定义逆行后当前进度到达时刻语义。增加同进度、不同到达时刻的用例。

### IR04｜P2｜速度效果设置没有应用到当前场景

- 位置：`client/main.ts:659`–`:665`；`World.motion` 仅在 `:96`、`:1031` 创建场景时赋值。
- 复现：设置中将“速度视角与车身晃动”从1调到0，返回同一赛道驾驶。设置值已保存，但当前 `world.motion` 仍为1，车身晃动/氮气视角仍开启；刷新或换赛道重建后才读取新值。
- 建议：设置变化时同步应用 `world.motion`，并将 motion 纳入设置类型。UI手动确认关闭、重新开启和刷新后保持即可，无需镜像实现测试。

### IR05｜P2｜普通单机AI赛未执行首完20秒窗口

- 位置：`client/main.ts:900`–`:955`。
- 原因：单机结束条件只有本地完赛、关卡limit和300秒上限。AI首位完赛不会锁定截止时间；server规则虽然实现正确，单机未使用该规则。
- 复现：普通单机AI竞速中AI在T秒先完赛，本地不冲线，在T+20之后仍可继续，直至本地冲线或300秒结束。若本地在T+25冲线，仍被当作合法FINISHED。
- 建议：普通单机竞速/道具赛使用相同的首完截止规则；教学与连续计时训练如果豁免，应显式分支和记入兼容决策。增加本地未完赛且AI首完、295秒首完两种用例。

### IR06｜P2｜单机结果表丢弃已计算的并列名次和DNF资格

- 位置：`client/main.ts:420`。
- 原因：`soloResult()` 已调用 `classify`，但结果行转为 `sorted.map((c,i) => i+1)`，每行名次重新使用数组位置。顶部本地名次与表格可相互矛盾；DNF行也显示数字名次。
- 复现：两辆完赛车的时间在权威分辨率内相同，`classify` 返回相同名次，表格却显示1、2；未完赛车显示后续数字名次和DNF文字并存。
- 建议：直接渲染分类结果的 `rank`，DNF用破折号/明确无名次，并让比赛HUD在完赛时沿用同一分类语义。

### IR07｜P3｜教学将内部99圈哨兵暴露为目标圈数

- 位置：`client/main.ts:730`–`:731`、`:758`–`:759`。
- 复现：进入五步教学，HUD显示 `LAP 1 / 99`；root实际浏览器操作已观察到，与源码一致。
- 原因：教学用99阻止普通圈数结束，HUD直接复用同一个目标值。
- 建议：教学显示当前训练步骤/已完成圈数，不将内部结束条件当成玩家目标。
