# HUD 特效与视觉冲击感：第二轮设计

日期：2026-09-09。状态：用户授权「全部完成」后已实施并验收。本轮只覆盖特效表现和必要的显示接入。下文保留制作前的设计依据；最终实现与实测结果见 [`acceptance.md`](../../../output/vfx-impact-20260909/acceptance.md)。

## 1. 结论与依据

建议采用「竞技仪表风格 + 短促、有方向的能量冲击」。先打磨起跑、漂移集气/收瓶、小喷、氮气、受击/挡击五条核心体验，再扩展比赛节点与名次结算。沿用明快卡丁车画面、青绿品牌色和现有 HUD 位置。

本次重新读取 countdown、hud、podium、race 特效及 main 显示接入；查看当前浏览器中低档矿山背景的 GO 定格。已有基础版解决了触发和生命周期问题，下一轮要提高造型、力度与不同事件的辨识度。下述时长、尺寸、透明度均为试制起点，尚无视觉或 GPU 达标结论。

具体不足：

1. 倒计时仍以通用 Arial 粗体、细四角框和柔和缩放为主。GO 的字级上限 138px，小于数字的 156px，当前曲线只有从小到大、停留、淡出，缺少更明确的爆发峰值。
2. 多数 HUD 提示通过同类 pulse 或 sweep 完成。命中、挡击与教学共用一个 marker；命中/挡击的轮廓区分不足，视觉语义主要落在颜色上。
3. 收瓶动画作用于全部 `.nitro-charge`，还没有表现「资源来自气槽、进入一个实际瓶位」的路径。世界粒子与 HUD 局部提示各自发生，缺少事件内的顺序。
4. 风线为固定 ±12°、620ms 循环，主要调整长度和透明度。启动、稳定高速与结束尚未形成明显差异。
5. 威胁使用宽度接近视口 70% 的完整圆环；小喷提示固定在屏幕 61% 高度。需要在实际驾驶视线和不同屏幕比例中重新标定。
6. 当前名次徽章核心为 56px；金/银/铜主入场分别为 2.4/1.8/1.4s，主要缩放幅度较小。可以将有力度的入场压缩到前 300–450ms，保留较长的余辉。

## 2. 视觉方向选择

| 方向 | 适配情况 | 决定 |
|---|---|---|
| 竞技仪表：硬边轮廓、分段刻度、短扫光、定向爆发 | 与现有赛车、青绿 HUD 和高速阅读契合；可复用现有技术 | 推荐作为主方向 |
| 全息仪表：多层圆环、网格、持续扫描 | 容易产生较多持续运动；与现有明快场景需要额外风格协调 | 只借用局部刻度与边缘线 |
| 强调大字：所有事件用放大文字和闪光 | 容易迅速建立焦点，但多个驾驶事件会争夺中央视线 | 大字保留给起跑与比赛关键结果 |

统一形态：切角、前倾、分段侧翼；实心字/亮芯承担辨识，硬轮廓承担结构，柔光只作辅层。资源、攻击和防御同时用形态与颜色区分。空闲边框保持低强度，仅事件发生的边段亮起。

## 3. 具体优化清单

| 优先级 / 对象 | 具体制作方法 | 成功条件 |
|---|---|---|
| P0 起跑数字与 GO | 数字增加清楚的暗色挤出边和窄高光；四角框升级为带三段刻度的左右侧翼。每拍数字落定、边框稍后锁合。最后 100–120ms 小幅收紧，真实放行后 GO 快速扩张、侧翼向外打开，留一道短暂描边残影 | GO 是整段最有力度的一拍；从准备到放行可以凭运动方向区分 |
| P0 集气、满气与收瓶 | 集气槽前沿增加亮头；满槽时端点聚光，收瓶后 2–3 条短能量带从槽端进入实际瓶位，瓶位先压缩再落定。库存已满保留稳定轮廓 | 玩家能看出资源的流向和到底获得了几瓶；每次收瓶不再让所有格子同时跳 |
| P0 氮气启动与持续 | 被消耗瓶位先释放短光带，速度仪表轮廓快速亮起，车尾点火与两侧向外掠过的速度线形成一个启动动作。随后风线减弱为持续层，结束时统一收束 | 一次使用可以清楚读出启动、持续、结束；接续使用没有第二次大爆发 |
| P0 小喷机会与触发 | 窗口使用靠近驾驶视线下缘的短双弧，开口随真实剩余时间收紧。使用时双弧向后拉开、暖色短焰同步启动；错过时直接收掉 | 机会与成功触发明显不同，500ms 机会仍有足够可读时间 |
| P0 受击与实际扣气 | 根据轻/中/重事件改变局部冲击幅度。车辆冲击点附近短亮芯、少量定向碎点，受影响 HUD 区块短位移回弹。扣气段保留约 180–250ms 残留条再退去，显示真实损失值 | 轻擦和重撞可区分；普通碰撞不会表现成扣气或掉瓶 |
| P0 护盾展开与挡击 | 开盾用闭合轮廓与车体边缘同步展开。挡击时先出现短白芯，再扩散为青蓝盾面波纹；HUD 用独立盾形标记收束 | 不读文字也能区分「挡住」与「被击中」 |
| P0 导弹来袭 | 完整大圆收为方向弧/箭头。越接近命中，弧线越短、越明确；紧迫提示只占对应方向的边缘区域 | 威胁方向始终可辨；不覆盖弯道、前车或持续遮住中央 |
| P1 道具拾取、使用及命中 | 世界拾取点先亮，HUD 槽随后落定；释放与命中使用不同形态。命中为短交叉标记，防御为盾形；成功反馈使用已有确认计数 | 同帧多个事件不会把一个图标挤成混合动画 |
| P1 换圈、目标、PB | 目标线完成后向对应 HUD 状态回收；圈数滚入、末圈短强调、PB 沿成绩一侧短扫光。只保留当前有效的提示 | 重要状态能够注意到，同时维持驾驶视线 |
| P1 第一/二/三名 | 放大并加强现有徽章主体的亮暗层次；第一名使用金色桂冠及扇形短光束，第二名使用银色双向弧，第三名使用铜色短放射。入场动作集中到前 300–450ms，星级稍后点亮 | 三种名次在静止和运动时都有明确差别，第一名具备最强峰值 |
| P2 环境与远车 | 校准已有烟、火花、雪、余烬的亮度和前景密度；主事件爆发时优先降低环境强调 | 关键操作与攻防始终是画面第一焦点 |

## 4. 三段重点动作的分镜

### GO：0–720ms

- 0–80ms：真实放行，GO 从约 0.8 倍快速到 1.14 倍；左右侧翼释放。亮芯出现一次。
- 80–200ms：主体回到 1 倍稳定；描边残影稍落后并淡出。最多 6 条短速度线由中心外侧掠向两边。
- 200–480ms：主体保持可读，边框和速度线退出；此时驾驶道路恢复为主焦点。
- 480–720ms：GO 短距离上移、淡出。低动态模式用静态 GO 后直接移除。

保留每个倒计时数字的真实持续区间；边框预收紧只读取剩余时间，暂停和延迟发车沿用当前语义。

### 收瓶：确认后约 300–380ms

- 0–60ms：已完成的气槽端点集中出光。
- 60–200ms：短能量带抵达对应库存格；源槽、路径、目标格形成同一个动作。
- 200–320ms：目标格压缩后回弹，留下稳定的满瓶轮廓。
- 若同帧消耗/补瓶使具体格子归属不唯一，使用整个库存轨道的短落定，避免编造瓶位；真实库存数字立即显示。

### 挡击：确认后约 320–420ms

- 0–50ms：盾面出现小范围亮芯；有可靠来袭方向时在对应一侧出现。
- 50–180ms：青蓝波纹沿盾面扩散，碎片向外散开。
- 180–350ms：HUD 盾形标记闭合落定；世界残光退出。
- 来袭方向无法可靠取得时，采用居中的盾面短波，不推测接触法线。

## 5. 冲击感的控制方法

1. **建立强弱等级。** 普通积累和待机为弱，收瓶/小喷为中，氮气启动/确认挡击/重撞为强，起跑与最终名次拥有独立的主视觉窗口。强度通过尺寸、速度、方向和亮暗变化组合，不只提高亮度。
2. **同一时刻最多一个主要 HUD 爆发。** 危险/受击/挡击优先于资源庆祝；必要方向提示常驻，低优先级只保留局部变化。过时的提示丢弃，不排队到危险过后再补播。
3. **连续层与爆发层分离。** 高速、盾持续、满槽轮廓保持稳定；短峰值用在事件边沿。连续氮气的第二瓶仅加强连接点。
4. **保护驾驶视线。** 赛车前方至弯心是主要留白区域。屏幕特效主要位于两侧、HUD 周围及短时主文字区域，平时没有中心遮罩。
5. **显示与规则分离。** 实际资源、名次、计时立即更新，残留条和过渡光属于装饰；不让动画延迟判定、输入或成绩。

## 6. 制作接入与性能口径

- `countdown.ts/.css`：重做造型和动画曲线，保留已验证的真实放行、暂停、长帧和清理逻辑。
- `hud-state.ts`：沿用确认状态；必要时补充事件类别/强度和同屏优先级，复用现有计数，不另建 gameplay 规则。
- `hud.ts/.css`：将资源轨迹、数字冲击、方向弧和状态边框组织为可复用的显示层；按 DOM 实际矩形定位，窗口变化时更新挂点。
- `driving.ts` / `race.ts`：只调整事件包络、形状、颜色与车体/HUD的同步，不改驾驶与道具判定。
- `podium-view.ts/.css`：加强奖牌主体与前 450ms 的入场，保留名次来源、去重、星级错峰和按钮可用性。
- 复用现有 high/low 粒子 768/192 与辅助实例 64/32 上限。试制优先使用少量复用 DOM / SVG；确需更多短线/碎片时再评估单个 Canvas 层，避免为每粒子创建 DOM。
- 低档减少光带、残影和次级碎片，保留大形与文字。motion=0 停止冲击位移、扫光和风线，保留静态状态。
- 新强反馈不追加全屏模糊、全屏高亮叠加或独立相机震动；速度空间感适配现有镜头变化。
- 1080p 前台八车进行开/关特效配对，记录 CPU、有效 GPU timer、绘制次数、DOM/合成开销；单元测试与旧 CPU 样本不证明新版本性能达标。

## 7. 实施顺序与验收

第一批制作起跑、收瓶、氮气、小喷四条短样片，放在相同真实赛道背景中与现版 A/B 对照。通过这一批确定统一的字形、边框厚度、峰值速度与余辉长度。

第二批用同一套强弱分级完成碰撞扣气、来袭、护盾与道具命中，重点检查组合场景：氮气中受击、同帧收瓶/用瓶、开盾后两弹来袭、盾挡与其他资源提示相遇。

第三批完成换圈/PB/名次，并做九图背景、窄屏、低档、低动态、长帧/重连及持续资源验收。

退出条件：无文字阅读时仍可区分启动/命中/挡击/收瓶；开场 GO 是整段最明显的视觉峰值；一次事件没有多次全屏强调；高档与低档都保留含义；按钮和驾驶输入立即可用；静止截图的字形和轮廓足够清楚，短视频能看出动作的预备、峰值和收束。

全部特效工作包已完成并接入游戏。验收包含最终65项特效回归、构建、全量测试及唯一计时失败的独立复跑、19图渲染扫描、窄屏/静态状态、十次重建和1080p前台CPU/GPU配对。实际性能样本存在长帧，不宣称稳定60fps；完整数据与视频保存在 `output/vfx-impact-20260909`。
