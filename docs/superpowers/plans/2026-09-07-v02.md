# PONS Kart 0.2 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for bounded physics work and review; integrate tightly coupled client/server changes locally. User authorized continuous execution.

**Goal:** Deliver the approved four-mode, nine-route racing upgrade with reliable collisions and measured performance.

**Architecture:** Immutable Track objects are passed explicitly into shared driving, AI, items and renderer. Match configuration is fixed server-side on creation. Solo uses the same simulation with local progression/ghost persistence. Existing SQLite economics remains unchanged.

**Tech Stack:** Existing TypeScript, Three.js, Colyseus, Node test runner; no new dependencies.

## Global constraints
- Chinese desktop UI, 2–4 real multiplayer players; no AI token payouts.
- All funds remain simulated and existing reservation/claim/refund rules remain intact.
- Three themes, nine distinct routes and unlockable career challenges, three AI difficulties with 3/5/7 opponents, racing/items/time-trial/free practice.
- Collisions and item use are authoritative on multiplayer server; client cannot submit positions/results/items owned.
- Preserve existing account data and completed original challenge records.
