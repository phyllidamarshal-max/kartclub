## 主要问题与修改

| 原有问题 | 接入后的处理 |
| --- | --- |
| 森林重复的巨大锥形树冠遮住路线，果园缺少区别 | 用圆冠、橡树、细冠、花树的实际 GLB 建立三个不同树种组合，按道路和捷径的完整边界留出树冠空间；保留原巨树地标位置与占地 |
| 海岸长路线种植稀疏，植物尺度偏小 | 按路线长度增加受限数量的树木和路肩草花，适度增大树木，保留村庄、海岸和道路间距 |
| 建筑、货箱、机械主块过硬，矿石轮廓过于规则 | 主体使用受限倒角，薄件保持简模；复用分层岩石几何，保留原模型包围尺寸 |
| 城市、港口、工厂、空间站及荒野长段缺乏沿路参照 | 增加主题一致的有限数量道具，按空间分块合并，标记为装饰资源并按画质裁剪 |
| 大面积地面过平，赛车背面与轮胎过暗 | 统一主光方位和中性补光；地面分别加入静态斑驳、混凝土接缝、沙纹和冰雪细节，保留每种地图的主色 |
| 解析地形公式与最终三角网格高度存在差值 | 实机发现果园个别树根悬空后，树木和路肩细节改为采样实际地形三角形高度；验证所有三种森林和主要道路边界 |

## 简洁视觉规范

- 方向：厚实的风格化体块、清楚的轮廓和材质分件，保留九种主题。道路及车辆的明暗与细节密度优先于背景装饰。
- 材质：涂装、金属、橡胶分别沿用已验收赛车材质；建筑主块有小倒角，主要金属件使用平滑法线，岩石保留切面。新地表细节均为静态材质，不增加事件效果。
- 灯光：普通地图固定世界主光方位 `(52,54,-33)`，与天空太阳方向一致。日景暖主光、冷中性补光；雪地使用冷白光。环境主题仍决定天空与地表颜色。海岸和专用参考路段保留已有照明参数。
- 普通地图曝光 1.08，海岸 1.05；夜景环境强度 0.72，普通日景 0.58。以上为当前 Three.js 管线中的实际值，不是跨引擎通用标准。
- 草地、沙地、冰雪、工业地面分别用克制的绿、赭、蓝白和灰色。城市/空间站/矿山保留夜景识别，补光不再让车身背面成为黑块。
- 已有 UI 继续使用项目的深绿、奶油白与亮绿体系。此轮检查地图预览和 HUD 的接入与布局，没有另行重做菜单和结算。

## 同条件性能记录及限制

设备：Windows 11 Pro，i7-12700KF，RTX 5060 Ti，Chrome 152、ANGLE D3D11。每次一个被测客户端，19 图顺序执行；画布真实 1280×720、DPR 1、8 辆固定位置赛车，同机位、同资源、同平台，高/低画质分别采样。每次 50 次预热、100 次 CPU 采样，使用 WebGL GPU timer query；原始 GPU 有效样本数记录在每份 JSON。前后均在采样期间停用已有事件特效更新，之后恢复。

检验页使用 MessageChannel 和 gl.finish，让离屏标签也能稳定完成采样。它包含 World 渲染和固定机位的额外提交，**不是正式游戏单帧耗时，也不是显示 FPS**。19 图均值：高画质 GPU 5.33 → 4.37 ms，低画质 2.37 → 2.15 ms；CPU 提交高画质 7.31 → 5.96 ms，低画质 4.22 → 3.91 ms。前后轮次存在波动，GPU 频率和后台负载未锁定，不能将这些差值解释为确定的性能提升。逐图数值、P95、原始样本和绘图统计均可在验收页下载。

原始性能采样曾发现 World.setQuality 改变画布尺寸；检验页已补上每帧画布尺寸检查，并覆盖重测全部 19 图高低画质记录。所有最终记录都带实际 drawingBuffer 校验。

基线与固定版本的赛道、AI、地图扩展、赛车资产和镜头运动定义经过一致性检查。同期其他任务加入了驾驶员外观可选字段；检验用 spawnCar 不传外观参数，物理与固定站位一致。多人、车库和角色开发并行进行，因此固定验收目录用于避免后续变化污染对照。

最终核对中，八个独立场景模块与固定版本一致；共享的 `world.ts` 在拍摄之后由角色任务增加了 DriverWardrobe 接入、角色释放和角色预览取景。本次场景集成部分保持一致，保留这些并行修改。最终构建与51项联合回归基于当前工作区，图片与性能基于固定版本。清单分别记录当前文件与固定文件哈希，不把角色更新后的性能冒充本轮测量结果。

## 实机与自动验证

- 19 图各 8 辆实际 AI 赛车，正式 stepCar 与 separateCars 运行 360 步（60 Hz，6 秒模拟），均为有限坐标，没有捕获页面异常。它是起步驾驶采样，不是逐图跑完一圈。
- 森林实际 6 秒录像已保存：1280×720、VP9、捕获上限 30 fps、无音轨。录制过程中执行 360 个物理步。文件 `after/forest-drive.webm`，编码文件时长约 5.96 秒。
- 七次森林切图中，每组树木 3 几何、3 材质、15 贴图与 143–158 个实例缓冲均恰好释放一次。旧 World 场景子对象为 0、车辆为 0、几何计数为 0。renderer 内部仍显示 1 个纹理计数，因此没有宣称 GPU 资源绝对归零。相同闲置地图重复进入的计数保持一致。
- 正式大厅选择巨木森林、进入自由练习、显示真实 HUD、暂停、返回大厅通过。地图选择页全部 19 张缩略图加载成功。地图选择页与森林 HUD 分别在 1280×720、1920×1080、2560×1080 检查，未发现水平溢出、关键面板越界或标题与底部操作区重叠。截图与矩形记录在 `ui-validation.json` 和 `after/ui-*.png`。
- 项目全量测试在集成阶段 700 项通过；随后树木贴地修正通过 36 项专项测试。最终 World 生命周期、贴地和森林资源联合回归 **51 项通过**。生产构建再次通过，保留原有共享脚本大于 800 KB 的分包提示。
- 八类场景道具通过真实 GLTFLoader 回读和 Blender 4.2.23 保存/重新打开验证，八组分件数、三角数、包围盒与轴转换一致，数据和变换均有限。
- 最后去除了路肩石块上重复的 toNonIndexed 调用，消除场景创建时的无害几何警告；该调用原来直接返回同一个非索引几何，因此外观与几何预算不变。修正后重新构建和运行51项联合测试，并在正式地图预览及森林练习中检查。浏览器扩展自身的警告另行保留在日志中。

尚未验证：19 图完整多人联机比赛、每图完整跑圈与结算/奖励端到端、低端 GPU 和移动设备、长时间声音/网络监听器统计。两张图片参考的严格像素 1:1 也不是本轮已经达成的结论。事件效果继续由对应负责人处理。
