| 场景 / 画质 | CPU 提交 ms | GPU ms | 末帧 calls |

| 3 车村落静态 / 高 | 0.992 → 0.910 | 1.767 → 1.992 | 219 → 214 |

8 车测试：真实 World、GLB、AI 和固定物理版本；120 帧预热、300 帧采样，1 次 1/60s 物理步/RAF，共 7 秒模拟，从起跑区出发，未到村落样板。为了排除并发任务的物理、车辆显示间距与镜头修改，两个版本都采用同一冻结物理、同一模型位置和测量追尾机位；事件特效 update 在测量中临时停用，finally 恢复。这不是整游戏 FPS 或完整特效成本测试。

村落测试：t=.281、固定正面相机、3 辆真实 GLB、60 帧预热+180 帧采样，仅计 renderer.render，包含正常场景与阴影绘制，不包含 AI、HUD 或音频更新。高画质 GPU 增加约 0.225ms，低画质约 0.090ms。村落更集中，近机位可见几何和阴影负担增加；不能用全局实例数量下降推断所有机位都更快。

12 对前后采样的车辆位置与相机位置/旋转均精确相同；5 组静态 PNG 的相机、画幅、场景 t、车辆位置均对齐。CPU 与 GPU 异步，不能把两者相加当作帧耗时。原始帧间隔保留，但浏览器 RAF 的运行模式不用于宣布某个产品 FPS。静态机位实际三角形与 calls 另存 performance-summary.json，三角形计数包含渲染通道，不能与单车几何预算混同。

低画质沿用现有方案：像素比 1，关闭实时阴影，细节块距离 105m、树木块 260m（均加 64m 空间块余量）；高画质相应为 165m/420m，正式游戏像素比上限 1.75。建筑仍保留远距离轮廓和关键信息。此处是本机测量，不给未测试手机或集成显卡承诺。

## 启动与复现

在仓库根目录运行 npm run dev，按终端显示的地址进入游戏。大厅 View kart 检查 Front / Side / Rear；选择 Sunny Bay Circuit 开赛，沿正式路线约 t=.235–.286 的村落段即可看到场景修改。设置中可切换高/低画质。当前报告 URL 是 /output/reference-replica-runtime-20260908/review.html。

查看精确样板：/output/reference-replica-runtime-20260908/lab.html?view=front&t=.281；后视参数 view=rear&t=.244，模型可用 model-front/model-side/model-rear。lab 是独立验证工具，运行实际 World 和 GLB，固定相机不影响游戏驾驶镜头。

要避开共享工作区未来变动，分别运行 npx vite --config output/reference-replica-runtime-20260908/vite-before.config.ts（5176/lab.html）及 vite-verified.config.ts（5178/lab.html）。后者运行归档的实际视觉版本及冻结物理，专用于样板/测量，不提供完整后端服务。正在运行的 5177 为本轮拍摄服务器，原始 before/after PNG 无需服务器也可打开。

重新生成模型：node --import tsx scripts/kart-assets/build.ts；随后 output/blender-runtime/Scripts/python.exe scripts/kart-assets/save_blend.py。执行 npm run build、npm test、npm run smoke 可复查当前共享仓库。重建聚合及报告：node output/reference-replica-runtime-20260908/build-delivery.mjs。
