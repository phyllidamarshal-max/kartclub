## 音色与交付

主要乐器和鼓组改用 Frank Wen 及贡献者制作的 FluidR3 GM 采样音库，按 MIT 许可使用；与原有合成器声音混合。许可和来源随成品保存在 `public/audio/music/CREDITS.txt`。这不是现场乐手演奏录音，也不是全部音色由本项目从零合成。

音库 SHA-256：`74594e8f4250680adf590507a306655a299935343583256f3b722c48a1bc1cb0`。来源为 Debian 的 fluid-soundfont-gm 3.1-5.2 包；只使用其中的音库，不安装 Debian 软件。TinySoundFont 0.3.7 仅用于离线渲染，放在本地独立目录中。

游戏只按需加载渲染后的 Ogg/AAC，共 18 个文件、16,840,978 字节；不会加载 148 MB 音库或 Python 依赖。采样率 44.1 kHz、立体声，每首为 32 小节，资源版本 `v=5`。客户端目录与实际导出速度、循环采样数保持一致。

新采样音色具有较高瞬态峰值；母带使用立体声联动的短前瞻峰值控制，以 -15.5 dBFS RMS 为参考，保持瞬态余量和段落动态。它不是 LUFS 归一化，也不用于声称音乐一定令人兴奋。音符、短混响和母带滤波以循环方式处理。音乐音量、0.8 秒换曲淡入淡出、用户点击解锁、暂停恢复和资源释放继续使用原有播放器。

## 本轮验证

- `check_composition.py`：9 首、144 个独立编写的小节，通过拍数、和声匹配、休止及转位检查。
- 全部 17 种采样乐器、13 种鼓组声音均可正常渲染。
- `validate.py`：18 个 Ogg/AAC 文件独立解码，时长、有效样本、峰值、静音和循环边界检查通过。
- 配乐目录/资产、播放器、碰撞音效及内容配置测试共 19/19 通过。
- 最终 `npm run build` 通过，构建 146 个模块；仍有原项目的较大分包提示。本轮未修改倒计时语音或 VFX 功能。
- 播放和数值检查不能代替主观听感；以试听页的真实音频比较为准。

## 修改与重建

- `scores.json`：名称、BPM、色板。
- `phrases.py`：完整八小节 A/B 旋律与和弦。
- `arcade_arrangements.py`：场景编制与鼓组。
- `sample_bank.py` / `instruments.py`：采样和合成音色。
- `arranger.py` / `mastering.py`：编排、混音与峰值控制。
- `render.py`：音频文件、片段和清单导出。

```powershell
python scripts/music/setup_band.py
python scripts/music/render.py
python scripts/music/check_composition.py
python scripts/music/validate.py
```

`setup_band.py` 下载并验证音库，安装固定版本的本地离线依赖；已经准备好时无需重复运行。修改 BPM 后还应同步 `client/music-catalog.ts`。试听中的旧版片段保留在 `output/music/previous/`，不被新渲染覆盖。
