# PONS KART · 逐浪车手

可在浏览器试玩的原创 3D 卡丁车原型：晴湾海岸、漂移集气与氮气、三个单人挑战、真实 2–4 人联机，以及持久化模拟门票和 PONS 奖池。

当前所有门票、税收和奖励均为模拟数据。没有部署链上合约、连接真实钱包或使用真实资金。

## 启动

需要 Node.js 24 或更新版本。首次运行：

```powershell
npm.cmd install --include=dev
npm.cmd run dev
```

打开 <http://localhost:5173>。启动命令同时启动网页（5173）和赛事服务器（2567）。`Ctrl+C` 停止两者。项目 `.npmrc` 明确安装开发依赖，避免本机全局 `omit=dev` 配置导致无法运行。

## 游玩

- **即刻试驾**：免费跑一圈，熟悉赛道。
- **单人挑战**：基础通关、55 秒限时、150 点累计漂移集气；进度保存在浏览器本地。
- **多人联机**：填写车手名，创建房间或输入好友的房间码。至少两人全部准备后自动扣票并开始。
- **奖励金库**：查看奖池分类、注入模拟交易税、领取完赛奖励。

默认方向键或 WASD 驾驶，Shift 漂移，Ctrl 氮气，R 回到已通过的检查点，Esc 打开菜单。单人菜单暂停计时；联机菜单不暂停比赛。设置中可改键、调整音乐和音效音量、切换流畅画质。氮气需要至少 100 点能量，每次消耗 100 点，最多储存 200 点。

同机测试多人时，请新建两个标签页，分别输入网址；不使用浏览器的“复制标签页”，因为它可能复制模拟账户身份。其他同一局域网电脑使用启动输出中的局域网地址；需能访问这台电脑的 5173 和 2567 端口。没有修改系统防火墙，也没有部署公网服务器。

## 模拟经济规则

金额存储为整数最小单位，100 最小单位 = 1 显示单位。

| 项目 | 规则 |
| --- | --- |
| 新账户 | 1,000 TICKET，0 PONS |
| 多人门票 | 每人 10 TICKET；全部准备时原子扣款 |
| 起始模拟基金 | 12,840 PONS，只初始化一次 |
| 每场奖金 | 开赛前预留 100 PONS；不足时不扣票、不开始 |
| 模拟税收按钮 | 模拟 5,000 PONS 应税交易额，按 2% 注入 100 PONS |
| 一人有效完赛 | 获得本场 100% |
| 两人有效完赛 | 70% / 30% |
| 三人及以上有效完赛 | 前三名 60% / 30% / 10% |
| 无人完赛 | 释放奖金；已进行的比赛保留门票收入 |
| 起跑前取消 | 退回门票，释放奖金 |
| 开赛后主动退出 | 未完赛者无奖励，不退票 |
| 服务器异常重启 | 将未结算比赛取消并退票，保留已结算奖励 |

房间正常运行最多 180 秒；第一位车手冲线后，其余车手最多再有 35 秒完赛。掉线保留席位 30 秒并尝试重连。

账本在 `data/economy.sqlite`；身份令牌散列在 `data/auth.sqlite`。这两个文件不提交 Git。测试使用独立临时数据库，不影响实际试玩余额。不要同时运行两个服务实例访问同一份数据目录。

## 修改角色、地图与音乐

编辑 `public/content.json` 后刷新浏览器：

- `palette`：四名车手的配色。
- `trackName` / `subtitle`：赛道名称和副标题。
- `ocean` / `grass`：场景颜色。
- `characterModel`：放入 `public/models/` 的 glTF/GLB 角色模型，如 `/models/sample-driver.gltf`。自带原创方头机器人示例，可直接试换。
- `sceneModel`：额外 glTF/GLB 场景装饰，世界原点加载；它不自动改变碰撞赛道。
- `modelScale`：外部模型比例。
- `musicUrl`：放在 `public/audio/` 中的自有音频路径；为空时使用原创程序化电子配乐。
- `challenges`：三个独立 ID 的挑战，可调整圈数、限时与累计集气目标。

资源路径以 `/` 开头，对应 `public/`。模型使用米制、Y 轴向上、Z 轴向前；角色挂载点在车身中心上方 0.9 米，建议角色高度约 1.3 米。模型替换失败会显示加载错误。外部模型的动画骨架与高级车辆挂点适配属于后续美术制作。

**改变实际赛道路线**：修改 `shared/track.ts` 的控制点，并同时重启服务器及刷新客户端。道路、边界、检查点和小地图从共享几何生成，避免画面与比赛判定分离。`client/world.ts` 控制海岛地形、建筑和装饰。当前几何版本为 `tide-coast-v1`，内容更新后不应让旧客户端加入新版本比赛。

## 工程与验证

```powershell
npm.cmd test       # 账本、驾驶、配置、键位与真实联机集成测试
npm.cmd run smoke # 两个测试客户端以正常输入跑完全场，验证结算和领取
npm.cmd run build # TypeScript 检查与生产静态资源构建
```

- `shared/`：可供客户端与服务器共同使用的驾驶、赛道和协议。
- `client/`：Three.js 原创场景、驾驶界面、声音与联机客户端。
- `server/`：权威比赛房间、模拟身份和 SQLite 账本。
- `public/`：可替换的资源配置与示例模型。
- `tests/`、`scripts/smoke.ts`：回归与完整比赛验证。

生产静态资源生成在 `dist/`，但单独打开 HTML 文件无法联机；仍需要赛事服务及 API 反向代理。当前交付方式为 `npm run dev`，未发布到公网。

## 当前品质边界

这是验证驾驶与联机经济闭环的首版，不是商业发行版。角色、场景和配乐是原创原型资产；漂移和氮气已有基础实现，尚未逐项调校到某个《跑跑卡丁车》版本的手感。未制作复杂道具赛、连续喷气技巧、8 人容量、移动端触控和真实链上支付。服务器校验能拒绝客户端伪造位置与成绩，但不代表完备反作弊。公网弱网、长期运营和更多设备性能仍需专项测试。

详见 `docs/verification.md`。
