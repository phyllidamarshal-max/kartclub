# PONS KART · 逐浪车手

0.2 浏览器 3D 赛车：三个主题、九条独立赛道、九关星级生涯、竞速 / 道具 / 计时影子 / 自由练习、三档 AI、真实 2–4 人联机，以及持久化模拟门票和 PONS 奖池。

当前所有门票、税收和奖励均为模拟数据。没有部署链上合约、连接真实钱包或使用真实资金。

## 启动

需要 Node.js 24 或更新版本。首次运行：

```powershell
npm.cmd install --include=dev
npm.cmd run dev
```

打开 <http://localhost:5173>。启动命令同时启动网页（5173）和赛事服务器（2567）。`Ctrl+C` 停止两者。项目 `.npmrc` 明确安装开发依赖，避免本机全局 `omit=dev` 配置导致无法运行。

## 游玩

- **即刻试驾 / 自由比赛**：从海岸、城市、山地的九条独立路线中选择地图，设置玩法、AI 难度、3 / 5 / 7 名对手和 1–3 圈。标准比赛为 3 圈。
- **竞速赛**：与 3–7 名 AI 比拼路线、漂移、氮气和碰撞卡位；AI 会感知前车、选择超车侧并控制接近速度。
- **道具赛**：拾取赛道上的金色道具箱；Space 使用加速、护盾、追踪飞弹或电磁陷阱。护盾持续 5 秒，飞弹优先锁定前方范围内对手，陷阱延迟激活并自动消失。
- **计时挑战**：每完成一圈记录轨迹，刷新个人最佳单圈时保存透明影子，下圈或下次比赛可追赶。
- **自由练习**：没有对手，可熟悉所有赛道。山地近道更窄，需要提前对准入口；障碍物会真实阻挡车辆。
- **单人生涯**：三个主题章节，每章竞速、计时和道具三关；每关实际路线不同，道路宽度逐步从 18 米收窄至 11 米，后期要求更多漂移、道具使用和更高名次。达到基本目标获得一星并解锁下一关；更快时间及更高排名获得二/三星。进度保存在浏览器。
- **多人联机**：创建前在赛事设置里选择地图、竞速或道具模式、圈数；房间显示实际规则。至少两名实际玩家全部准备后扣票开始，AI 不参与奖池比赛。

方向键或 WASD 驾驶，Shift 漂移，Ctrl 氮气，Space 使用道具，R 回检查点，Esc 菜单。单人菜单暂停计时，联机菜单不暂停比赛。设置支持改键、独立音乐/音效音量和流畅画质。氮气每次消耗 100 点，最多存储 200 点。

碰撞采用街机模型：侧挤和追尾传递有界动量；擦墙保留切向运动，正面撞击明显减速；障碍有扫掠检测。重置后 2 秒跳过车车碰撞，但仍受道路与障碍约束，按住重置不会持续刷新保护。

同机测试多人时，请新建两个标签页，分别输入网址；不使用浏览器的“复制标签页”，因为它可能复制模拟账户身份。其他同一局域网电脑使用启动输出中的局域网地址；需能访问这台电脑的 5173 和 2567 端口。没有修改系统防火墙，也没有部署公网服务器。

## 模拟经济规则

金额存储为整数最小单位，100 最小单位 = 1 显示单位。

| 项目 | 规则 |
| --- | --- |
| 新账户 | 1,000 TICKET，0 PONS |
| 多人门票 | 每人 10 TICKET；全部准备时原子扣款 |
| 起始模拟基金 | 12,840 PONS，只初始化一次 |
| 每场奖金 | 开赛前预留 100 PONS；不足时不扣票、不开始 |
| 模拟税收按钮 | 模拟 5,000 PONS 应税交易额，按 2% 注入 100 PONS |
| 一人有效完赛 | 获得本场 100% |
| 两人有效完赛 | 70% / 30% |
| 三人及以上有效完赛 | 前三名 60% / 30% / 10% |
| 无人完赛 | 释放奖金；已进行的比赛保留门票收入 |
| 起跑前取消 | 退回门票，释放奖金 |
| 开赛后主动退出 | 未完赛者无奖励，不退票 |
| 服务器异常重启 | 将未结算比赛取消并退票，保留已结算奖励 |

房间最多运行每圈 180 秒（3 圈上限 540 秒）；第一位车手冲线后，其余车手最多再有 35 秒完赛。掉线保留席位 30 秒并尝试重连。

账本在 `data/economy.sqlite`；身份令牌散列在 `data/auth.sqlite`。这两个文件不提交 Git。测试使用独立临时数据库，不影响实际试玩余额。不要同时运行两个服务实例访问同一份数据目录。

## 修改角色、地图与音乐

编辑 `public/content.json` 后刷新浏览器：

- `palette`：四名车手的配色。
- `trackName` / `subtitle`：赛道名称和副标题。
- `ocean` / `grass`：场景颜色。
- `characterModel`：放入 `public/models/` 的 glTF/GLB 角色模型，如 `/models/sample-driver.gltf`。自带原创方头机器人示例，可直接试换。
- `sceneModel`：额外 glTF/GLB 场景装饰，世界原点加载；它不自动改变碰撞赛道。
- `modelScale`：外部模型比例。
- `musicUrl`：放在 `public/audio/` 中的自有音频路径；为空时使用原创程序化电子配乐。
- `challenges`：保留首版三关的资源格式；0.2 九关的目标与星级由 `shared/gameplay.ts` 的 `CHALLENGES` 定义。修改这里并刷新以调整新生涯。

资源路径以 `/` 开头，对应 `public/`。模型使用米制、Y 轴向上、Z 轴向前；角色挂载点在车身中心上方 0.9 米，建议角色高度约 1.3 米。模型替换失败会显示加载错误。外部模型的动画骨架与高级车辆挂点适配属于后续美术制作。

**改变实际赛道路线**：修改 `shared/track.ts` 或 `shared/route-data.ts` 中相应地图的控制点，并同时重启服务器及刷新客户端。道路、边界、检查点和小地图从共享几何生成，避免画面与比赛判定分离。`client/world.ts` 控制海岛地形、建筑和装饰。九条新地图 ID 为 `coast` / `coast-harbor` / `coast-breakwater` / `city` / `city-factory` / `city-nightshift` / `mountain` / `mountain-pass` / `mountain-summit`；旧 `tide-coast-v1` 保留用于回归测试。Track 定义供服务器、AI、道路、障碍、小地图和高度渲染共用。修改后同时重启服务及刷新所有客户端。

## 工程与验证

```powershell
npm.cmd test       # 账本、驾驶、配置、键位与真实联机集成测试
npm.cmd run smoke # 两个实际测试客户端跑完旧地图回归赛事，验证结算和领取
npm.cmd run build # TypeScript 检查与生产静态资源构建
```

- `shared/`：可供客户端与服务器共同使用的驾驶、赛道和协议。
- `client/`：Three.js 原创场景、驾驶界面、声音与联机客户端。
- `server/`：权威比赛房间、模拟身份和 SQLite 账本。
- `public/`：可替换的资源配置与示例模型。
- `tests/`、`scripts/smoke.ts`：回归与完整比赛验证。

生产静态资源生成在 `dist/`，但单独打开 HTML 文件无法联机；仍需要赛事服务及 API 反向代理。当前交付方式为 `npm run dev`，未发布到公网。

## 性能与完整新赛事验证

启动开发服务后打开 <http://localhost:5173/bench.html>，运行独立的四条代表赛道的八车道具场景基准（固定 1920×1080 渲染缓冲，流畅档）。它不读账户、不计成绩。请保持测试页在前台；约 1 秒一次的后台节流样本会标记无效，不能解释成游戏实际帧率。测试后可返回主游戏。

新三圈道具赛事的真实 SDK 验证：

```powershell
$env:SMOKE_TRACK='coast'
$env:SMOKE_MODE='items'
$env:SMOKE_LAPS='3'
npm.cmd run smoke
```

## 当前品质边界

这是持续迭代的原创浏览器游戏。已实现多模式、九条路线和碰撞升级，但不声称等同商业版《跑跑卡丁车》的完整内容、美术或内部驾驶公式。公网弱网和多设备容量尚需进一步测试，尚未接入真实钱包、链上合约、商城或正式组队赛事。

实测、审查和限制见 `docs/v02-verification.md`。
